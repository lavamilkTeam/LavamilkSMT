# 通信协议

此目录是跨模块协议约定的唯一来源。

已实现：[局域网发现与连接 v1](lan-connection-v1.md)，使用 mDNS 发现、TCP JSON Lines 长连接，
支持握手、心跳及只读状态查询。以下业务协议仍待确定。

另有 [OpenCV 预览 HTTP v1](preview-http-v1.md)，通过独立端口 8766 传输处理后的相机画面。

## Console 面板与 controller

两者部署在同一台 Linux 上位机，仍通过明确接口协作。浏览器访问终端与本地开发客户端
不拥有机器执行权；局域网发现与只读连接继续保留给外部客户端。

- 设备状态与坐标字段、长度及角度单位。
- 点动、回零、真空、任务启动/暂停/停止等操作接口。
- 状态事件、任务数据与业务错误格式；基础连接协议见上述 v1 文档。
- 重复请求识别、控制权和断线后的处理方式。

## Linux 控制板与下位机

- 物理通信接口、帧格式、命令编号与协议版本。
- 单位、坐标方向、绝对/相对位置和速度含义。
- 命令接收确认、执行完成、失败与设备状态回复。
- 超时、重复报文、重连、停止和重启后的状态确认。

## 更新服务

- MCU 更新检查已实现：console → Python controller → Go mcu-updater；[接口定义](mcu-update-v1.md)。
- host-updater 的上位机自身更新尚未实现，仍由 Python 协调维护后交给独立服务执行。
- 两个 updater 均运行在上位机，与 controller 协调同一份维护状态；更新之间互斥，并与运动互斥。
- 需定义更新任务 ID、目标类型、版本、兼容性、进度、错误、幂等与断线重查规则。
- controller 重启不能丢失维护约束；更新后先核对设备状态，不能自动恢复贴装。
- Go MCU 服务提供本机 Unix socket API；维护许可消费已实现，Python 真实硬件维护适配尚未接入，面板不会触发烧录。整体边界见[架构约定](../docs/architecture.md#更新服务边界)。

协议确定后，在此保存说明、报文样例及必要的机器可读定义。不能将“收到命令”当作“电机已完成运动”。
